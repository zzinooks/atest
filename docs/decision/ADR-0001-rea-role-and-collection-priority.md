# ADR-0001: REA의 역할과 데이터 수집 경로 우선순위

- 상태: 승인 (2026-11-04, STEP 1)
- 작성 일자: 2026-11-04

## 배경
마스터 프롬프트는 REA를 "API 분석 및 생성 도구"로 정의했으나, 실제 REA(morluto/rea)는 APK·바이너리·기록된 트래픽을
로컬에서 분석하는 도구다. 또한 바로잰 Fit은 공식 앱(바로잰 Care)에서 가족 공유를, 삼성 헬스·Apple Health로 데이터 전송을 이미 지원한다.

## 결정
1. REA는 **개발 단계의 분석 도구**로만 사용한다. 운영 코드는 REA에 의존하지 않는다.
2. 수집 경로는 다음 순서로 평가하고, 앞 순위가 요구사항을 충족하면 뒤 순위는 조사만 하고 구현하지 않는다.
   1) 제조사 공식 API·제휴
   2) Health Connect (Android 공식 플랫폼, 사용자 동의 기반)
   3) Samsung Health Data SDK (공식 SDK, 배포 조건 확인 필요)
   4) REA로 분석한 비공식 API — **본인 계정 PoC 한정**. 운영 사용은 약관·법적 검토 후 별도 ADR로만 허용
3. 어떤 경로든 `GlucoseSourceAdapter` 뒤에 두어 교체 가능하게 한다.

## 결과
- 장점: 약관 위반·계정 차단·API 변경으로 서비스가 갑자기 멈출 위험을 줄인다. 혈당 알림 서비스는 수집이 끊기면 안전 문제가 된다.
- 단점: 공식 경로는 지연(예: 플랫폼 동기화 주기)이 클 수 있다. 지연 측정은 STEP 2 PoC에서 수치로 확인한다.
