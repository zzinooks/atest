# REA 대상 유형별 플레이북

각 플레이북은 SKILL.md의 1~4단계에서 "무엇을 먼저 보고, 어떤 도구를 쓰고, 무엇을 놓치기 쉬운지"를 정리한다.

## 1. 소프트웨어 · 소스코드
- 진입점부터: `main`, 라우터/컨트롤러, 스케줄러, 메시지 리스너, 설정 파일(`pom.xml`, `package.json`, `*.yml`).
- 빌드/의존성 → 프레임워크 → 모듈 경계 → 도메인 엔티티 → 핵심 유스케이스 순.
- 주요 흐름 하나를 요청~응답까지 끝까지 추적(call chain)한 뒤 넓힌다.
- 놓치기 쉬운 것: 설정·환경변수로 바뀌는 동작, 리플렉션/DI로 숨은 호출, 배치·트리거·DB 프로시저 속 로직.

## 2. 바이너리 · 통신 프로토콜
- `file`, `strings`, `xxd`, `objdump -d`, 패킷 캡처(pcap) 등으로 형식부터 식별.
- 프로토콜: 프레이밍(헤더·길이·구분자·체크섬) → 메시지 타입 → 필드 → 시퀀스(핸드셰이크, ACK/NAK, 재전송, 타임아웃).
- 같은 동작을 입력만 바꿔 여러 번 캡처해 **차이(diff)** 로 필드 의미를 찾는다.
- 산업 표준이 있으면 먼저 대조한다 (예: SECS/GEM·HSMS, Modbus, OPC UA, MQTT, PLC 벤더 프로토콜).
- 놓치기 쉬운 것: 엔디언, 패딩, 시퀀스 번호 롤오버, 타임아웃/재시도 정책.

## 3. 데이터 · DB · 로그
- 스키마 → 키/인덱스 → 테이블 간 관계 → 상태 컬럼 값 분포(`SELECT status, COUNT(*) ... GROUP BY`) 순.
- 이력/로그 테이블로 **상태 전이 그래프**를 실제 데이터에서 추출한다 (from→to 빈도표).
- 로그: 메시지 템플릿을 클러스터링해 이벤트 종류를 목록화하고, 하나의 ID(작업·캐리어·주문)로 타임라인을 재구성.
- 놓치기 쉬운 것: 소프트 삭제 플래그, 코드값 의미(공통코드 테이블), 시간대(UTC/로컬), 야간 배치로 바뀌는 데이터.

## 4. 제품 · UI · 웹서비스
- 화면 목록 → 내비게이션 맵 → 각 화면의 입력/출력/권한 → 네트워크 요청(API) 대응.
- Playwright로 화면과 네트워크 요청을 기록해 화면↔API↔데이터를 매핑한다.
- 놓치기 쉬운 것: 권한별로 달라지는 화면, 빈 상태/에러 상태, 비동기 갱신(폴링·웹소켓).

## 5. 문서 · 콘텐츠 · 글
- 구조(목차·단락 역할) → 논증 흐름 → 설득 장치(사례·수치·대비·반복) → 문체 규칙.
- 산출: "이 글을 다시 쓰기 위한 템플릿 + 작성 규칙".
- 놓치기 쉬운 것: 대상 독자 가정, 의도적으로 생략된 내용.

## 6. 업무 프로세스 · 조직
- 액터(RACI) → 트리거 이벤트 → 단계 → 산출물 → 승인/분기 → 예외 처리 → KPI.
- 문서상 프로세스(As-Designed)와 실제 프로세스(As-Is)를 구분한다. 차이 자체가 핵심 발견이다.
- 놓치기 쉬운 것: 비공식 우회(엑셀·메신저), 특정 담당자에게만 있는 암묵지.

## 7. 비즈니스 모델 · 전략
- 고객 세그먼트 → 가치 제안 → 채널 → 수익 구조 → 비용 구조 → 핵심 자원/파트너 → 해자(Moat).
- 가격·공개 재무·채용 공고·제품 변경 이력에서 의도를 추론한다. 모든 수치는 출처와 근거 등급을 붙인다.

## 8. 물리 시스템 · 설비 제어 (물류 자동화 / MCS 포함)
계층부터 고정한다:
```
ERP/WMS/MES  ──  상위 지시(주문·작업·반송 요청)
     │
   MCS/WCS   ──  반송 경로 결정, 작업 분배, 재고·위치 관리, 설비 상태 관리
     │
 설비 컨트롤러 (Stocker·OHT/AGV/AMR·컨베이어·셔틀·크레인 제어기, PLC)
     │
   센서·액추에이터
```
- **인터페이스 목록**: 상위/하위 각 I/F의 프로토콜·메시지·주기·타임아웃 (예: 반송 명령, 완료 보고, 알람, 상태 보고).
- **반송 작업 상태 기계**: 생성 → 할당 → 출발 → 이동 → 도착 → 완료 / 취소·중단·재시도·수동 처리. 이력 데이터로 실제 전이를 검증.
- **경로·배차 로직**: 최단경로인지, 부하·우선순위·예약(Reservation)·데드락 회피 규칙이 있는지. 다양한 출발/도착 조합의 실적 데이터로 역추적.
- **위치/재고 모델**: Port·Shelf·Zone·Buffer 체계, 캐리어 ID와 위치의 정합성 보장 방식(리더기 재확인, 불일치 처리).
- **알람·예외**: 알람 코드 체계, 자동 복구 vs 수동 개입 기준, 이중반입·공출고·ID 불일치(Mismatch) 처리.
- **성능·용량**: 시간당 처리량(Throughput), 사이클타임, 병목 설비, 피크 시나리오.
- 놓치기 쉬운 것: 현장에서 수동 조작으로 생긴 데이터 불일치, PLC 측에 숨어 있는 인터락 로직, 야간·정기 PM 시 운영 모드 전환.
